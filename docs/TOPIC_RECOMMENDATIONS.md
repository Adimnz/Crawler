# Topic investment research

The observation board now has a separate investment research panel. It answers
which topic-connected assets are supported, whether a measured entry rule clears
validation, the holding horizon, and the conditional historical return range.
It can return **Wait / insufficient evidence**. It never inserts a price,
expected return, probability, cost or confidence rating generated by an LLM.

## Evidence scope and asset discovery

Every stored document is screened against the selected topic and all saved
research branches. Candidates require provider-verified equity or crypto identity
and a cited source connection. The panel lists the number of documents screened,
relevant records, branches, candidates, and all relevant source versions in its
JSON export. Manual board assertions do not become investment evidence.

A source text match establishes research relevance, not revenue exposure or a
causal price relationship. Current exact quotations and an enabled primary source
are required for entry eligibility. Revised, disputed or retracted relevant
records and pending topic reassessment withhold entries. Source disabling, price
revisions, new claims and changes to branch research invalidate cached results.

This covers the application's collected records. It cannot claim to include all
information on the internet, private records, paywalled material or undiscovered
connections. Existing acquisition/model extraction limits still apply to what the
application has collected. All retained records are screened without a hidden
latest-10,000 cutoff, using database keyset batches.

## Fixed first model

Version `topic-analogues-1` uses:

- 20 source-session momentum and standard deviation of daily log returns.
- Up to 40 nearest earlier cases, with distances scaled by training-only feature
  standard deviations. At least 30 training cases are required.
- Entry at the next available source session, followed by a five-source-session
  horizon. This is a hypothetical daily-price convention, not an executable fill.
- Cases spaced six source sessions apart; training labels must have ended and
  become available strictly before the validation decision. The first 30 cases
  cannot be validation cases. No shuffled split or best-performing horizon search.
- At least 20 held-out forecasts and 10 held-out entry signals. The model must beat
  the unconditional historical-median baseline on mean absolute error in the same
  chronological folds. Held-out entry returns must also clear the stated
  positive-return gate after costs.
- Entry rule: current features must be within the observed training range, with positive current momentum and positive analogue mean minus 1.96
  standard errors. The same approximate gate is applied to held-out signal returns.
  This is a declared research policy, **not** a calibrated 95% guarantee. Serial
  dependence, regime changes, multiple-candidate selection and universe selection
  bias can remain even with non-overlapping outcome windows.
- Median and 10th/90th percentiles of observed analogue returns; these are
  conditional model estimates, not proven probabilities or prediction intervals.
- At most 1,500 daily sessions per model assessment, with excluded older sessions
  counted visibly. The model uses one consistent provider/currency/adjustment
  series. A newer comparable quote moving beyond the declared review threshold withdraws the daily entry signal. Other comparable current providers are checked for disagreement beyond
  the declared 1% review threshold. Missing or incompatible inputs are excluded.

Each export includes source observation values, identifiers, currency, adjustment,
provider URLs, timestamps, feature values, sample entry/exit dates, purged fold
boundaries, baseline errors and downside cases. Numerical estimates are withheld
as recommendations if any evidence, freshness, cost or validation gate fails.
Exploratory analogue statistics can still be inspected with that label.

Financial statements, costs, contracts, macroeconomic and news records establish
relevance and evidence validity. **This first model does not learn their numerical
price impacts.** Assigning arbitrary positive/negative return weights to articles
would invent information. A future multivariate model needs timestamped feature
histories and separate chronological validation before those effects can enter a
return estimate. The current price-model validation also does not establish that
the topic-selection process would have worked historically.

## Data and cost setup

The server owner supplies the estimated total round-trip fee/slippage assumption
in the panel. No implicit zero-cost estimate is used. The first version uses a
single disclosed basis-point assumption for all candidates; it is not a provider
measurement or an estimate of individual liquidity or tax costs.

Crypto history can use the existing CoinGecko asset connector. Downloaded history
remains backfilled history. It cannot fabricate an earlier issued entry signal.
The local retrieval and availability gates must support each validation decision;
a fresh installation can correctly withhold recommendations for lack of such
history. New prospective observations gradually provide usable cases.

SEC filings alone do not contain a daily stock-price history. A new optional
`equity_daily` connector fetches Alpha Vantage adjusted daily closes and verifies
currency/symbol against its company overview and identity against the SEC
catalogue. Enable a registered source explicitly, with:

```json
{
  "kind": "equity_daily",
  "url": "https://www.alphavantage.co/query",
  "config": {
    "assetId": "equity:EXCHANGE:PROVIDER_VERIFIED_TICKER",
    "ticker": "PROVIDER_VERIFIED_TICKER",
    "outputsize": "full"
  }
}
```

Replace the placeholders with an existing provider-resolved identity. Set
`ALPHAVANTAGE_API_KEY` and the existing `SEC_USER_AGENT` on the server. Never put
credentials into a source URL or configuration JSON. Alpha Vantage entitlement
and rate limits apply; compact history can be insufficient. Provider errors do
not fall back to raw prices or made-up values. Adjusted closes include split and
cash-dividend adjustments and are not executable market quotes.

Provider documentation: https://www.alphavantage.co/documentation/#dailyadj

## Refresh, lifeline and revision history

The visible panel reads a compact cached view every 10 seconds, with backoff on server pressure. Missing or stale calculations return HTTP 202 and run once in the existing background worker queue. Replay arrays and full source manifests are loaded only by the explicit export request; the HTTP read never runs the model. Any relevant dataset write invalidates
the cache; a price older than 36 hours expires entry eligibility even without a new
record. The clock is also checked client-side, and transport failure clears active
recommendations. Five source sessions describe the analysis horizon; no future
calendar date or guaranteed holding outcome is invented.

Previously assessed boards receive background reviews through the existing worker
queue, at most four queued per scheduler pass. Dataset signatures suppress
unchanged work; clock-based cache lifetimes are bounded to five minutes or an
earlier price expiry. Existing worker/thread limits and leases apply. Stopping or
pausing topic research withdraws active entries. Board deletion removes its
private recommendation snapshots and revisions.

Snapshots have append-only material revisions and a change explanation. A new
source, correction, asset price, cost input or expiration can revise or withdraw
an entry. Inputs changing during computation suppress the result until the next
assessment. This does not imply instantaneous discovery of information that the
application has not collected.
